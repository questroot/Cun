# 按实机结果推进的路线图

不设虚构日期、人数或固定玩法。每阶段只选择一个最影响下一步的未知项，文档服务测试，不以页数或功能数量衡量进度。[现有原型](../card-demo/project.godot)可以提供实验材料，但不因此被选为正式方向。

当前已有[石化世界候选规划](design/project-plan.md)和[首个可玩版本计划](design/first-playable.md)。下面是通用阶段门槛；候选计划细化工作，不跳过方向确认与真实试玩。

## 1. 方向探索

**做什么**：用户与伙伴各提出少量候选，用[游戏简报](templates/game-brief.md)说清玩家行为、目标体验和最大风险。每次只验证一个假设，采用低成本可操作原型；已有原型是否参与由团队决定。

**实机出口**：真实操作者能完成一次候选玩法的核心行为；记录其操作、卡点和是否愿意再玩。对比候选的体验、实现成本和授权风险，团队明确选一个继续，或决定继续探索。一次好评不等于市场结论。

**停下或回退**：关键行为无法传达、体验证据不支持假设，或成本/授权风险不可接受时缩小、换候选或放弃，不为了保留代码硬选方向。

## 2. 可玩闭环

**前提**：已确认暂定方向、目标平台、引擎及正式工程位置；这些目前均待确认。

**做什么**：只实现“开始 → 核心操作 → 反馈/结果 → 重试或退出”。优先占位资源，暂缓外围系统与内容量；定义一次完整游玩的长度与结束条件。

**实机出口**：另一人能从约定的启动方式进入并完成一轮，无需开发者代操作；能理解目标与主要反馈，结果后可重试/退出，主路径没有阻断问题。通过[试玩记录](templates/playtest.md)留下具体证据，无法理解时先改善闭环，而不是加系统。

## 3. 纵切

**前提**：闭环已在目标设备验证，核心体验值得继续。

**做什么**：选一小段代表性内容，让规则、交互、画面、声音和必要持久化一起达到暂定质量目标；不要求做完整游戏或提前加入联网。

**实机出口**：在约定目标设备上重复完成代表性流程，记录加载、帧时间/卡顿、输入与视听问题；按事先约定的性能和质量阈值检查。若包含存档，实际验证退出再进入与失败读档路径。阈值需测试前确定，不能事后为通过而放宽。

**下一步**：团队依据试玩与制作成本决定扩大内容、调整方向或停止。发行平台、商业模式、预算和许可仍须独立确认，不由纵切成功自动授权。

## 每次测试后的三种结论

继续 / 调整后复测 / 停止；每次写清证据、下一项操作和负责人。所有阶段出口目前都是待验证的判据，不是已取得的成果。
