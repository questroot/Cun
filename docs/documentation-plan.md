# 文档规划：单一事实入口与工作过程维护

## 1. 范围和“实时”的准确含义

当前明确任务是现有 Godot 原型的 Windows 启动器、架构/文档维护规划，以及由有权限负责人处理 GitHub 交付。原型玩法不变；正式游戏方向仍未定，不默认建立真 3D 新工程，不启联网或运行时 LLM。技术层次见[架构边界](architecture.md)，候选玩法仍见[候选规划](design/project-plan.md)。

**实时 = 工作过程中维护共享事实 + 启动器打开/刷新时生成本机快照。** 不存在持续监听仓库的服务；关闭启动器后不承诺更新，打开后也不因文件变化而承诺自动重算。`.local/project-snapshot.md` 是本机生成摘要，不是后台监控、源文件替代品或批准记录。刷新只是重新观察，不是游戏验收。

开始工作时读[共享现状](../PROJECT_STATUS.md)和任务相关规格；结束时核对事实及受影响文档。**只有阅读、无新事实或无更正时，不必修改文档，不得为“实时”编造进度、试玩通过或批准记录。** 本规划规定维护职责，实际启动器检查、引擎运行和上传状态以共享现状为准，不由文档本身宣布通过。

## 2. 每类信息只有一个主责位置

| 位置 / 类型 | 职责与权威 | 不负责 / 更新者 |
| --- | --- | --- |
| [共享现状](../PROJECT_STATUS.md)（本次由主代理建立/维护） | 当前任务、已实现范围、真实验证、阻断和下一步的共享入口；应引用源码/记录而非复制全文 | 不替代源码、方向批准或测试证据。当前文件所有者汇总执行者的有证据结果 |
| [Agent 工作规则](../AGENTS.md)（本次由主代理维护） | 约定开始读取共享现状/相关规格、结束核对事实及权限边界 | 不是任务进度账；执行者遵守，不在此重复状态 |
| 已批准决策（按需使用[决策模板](templates/decision.md)） | 仅真实状态为“已确认”、有确认者/日期/适用范围和证据的记录，定义正式选择；替代关系显式引用 | 模板存在、AI 建议、个人摘要或投票不算批准。获授权记录者更新，决策人确认 |
| [候选方向](design/project-plan.md) / [候选首个可玩计划](design/first-playable.md) | 方案、假设、依赖和候选验收；保留分歧，不当作授权开工 | 方案整理者在新信息/获批变化时更新；正式决策应链接回这里，不复制一套正典 |
| [想法池](design/ideas.md) | 新点子原意、来源类别、澄清问题、关联编号及真实状态 | 收录不等于采纳。提出者确认原意，整理者维护关联；不放私人对话原文或未经许可身份信息 |
| [40 题问题总表](design/questions.md) | 未决题目、候选与取舍的讨论索引 | 不自动把某选项视为团队答案；题目维护者核对受影响题 |
| [40 题 Agent 包](design/agent-discussion-kit.md) | 供个人带给自己 Agent 的自包含讨论材料与提示；允许必要背景摘要 | 是分享副本，不是新增正典、不集中收票。维护者在共享背景/候选改变后核对版本与状态，个人私有回答不入库 |
| [文档导航](README.md) / [架构边界](architecture.md) / 本文 | 分别负责入口、层次与接口边界、文档维护规则 | 不复制每个玩法规格或完整进度。导航的新增入口由有权限负责人维护；架构在边界变化时更新 |
| 源码、配置、资源及真实验证记录 | 对“当前实现是什么”优先核源文件；对“是否运行通过”优先核真实操作和输出，例：[项目配置](../card-demo/project.godot)、[数据管理器](../card-demo/scripts/managers/data_manager.gd) | 源码存在不等于实测成功；配置版本不等于本机版本。实现者提供受影响路径和验证范围 |
| `.local/project-snapshot.md`（本次启动器生成） | 打开/刷新时生成的本机环境、项目观察与文档入口摘要；具体字段以启动器实现为准 | 本机配置/日志/快照均在忽略目录，不提交；不自动改写共享状态，不确认玩法、团队决策或 GitHub 上传 |

冲突时按问题性质解决：**实施授权/游戏方向核当前明确授权和已批准决策；实现事实核源码；运行事实核真实验证；本机环境核当次探测。** 共享现状负责给出入口和边界；文档与源码冲突须标记并修正受影响位置，不能为了消除矛盾擅自修改玩法。候选文档的状态不因技术启动器获批而转为游戏方向获批。

只在自身职责内摘要，其余引用主责位置。Agent 包因离线使用允许背景副本，但须明确版本、候选性质和验证边界；它的陈旧信息不是推翻新证据的理由，也不得在每次读文件时自动改版本。

## 3. 谁在何时核对和更新

### 开始工作

1. 执行者读取工作规则、共享现状和当前明确授权，确认任务/目录写权限与现有文件所有者。
2. 按需读相关规格、决策和少量源码；查看“已存在 / 本次新增 / 未来建议”，不把未验证项升级为完成。
3. 发现矛盾时先提供源路径与具体差异；影响并行工作时尽早通知负责人，不等待最终汇报。

### 工作过程中

- 边界、接口、数据格式或来源许可发生变化时，先核获批范围，再更新相应主责文档；仅局部实现细节不必新建完整规格。
- 真正新增想法进想法池；方案比较进候选规划；批准进决策记录；任务事实进共享现状。不要把这些混在一个“实时日志”中。
- 实现者提供实际修改路径、已做检查和未做检查；共享文件所有者据此合并，不用助手推测填补缺失结果。
- 打开/刷新启动器生成本机快照；若需重查，只进行一次明确刷新，不假设后台已更新。快照不能自动清除阻断或写入“通过”。

### 结束工作 / 交接

1. 对照实际差异核对受影响文档及相对链接；确认实现描述与源码一致，候选仍有状态标记。
2. 有新事实、更正或实际验证结果时，在权限范围内更新主责文件；不拥有文件时提交有界交接给所有者，不越权编辑。
3. 交接至少列出：修改文件、关键差异、证据路径/操作、结果、未验证项、并行冲突和待负责人动作。不提交无关私人会话内容。
4. 只有文档核对时写“文档核对”，只有静态/核心测试时写相应范围；没有 GUI 点击、引擎进程或完整玩法证据，就保留对应未验证项。

## 4. 受影响路径与证据映射

| 触发变化 | 必须核对的主责位置 | 足够且真实的证据例子 |
| --- | --- | --- |
| 启动器探测、启动模式、配置或诊断变化 | 启动器核心/界面、[架构](architecture.md)、[共享现状](../PROJECT_STATUS.md)；本机快照重新刷新 | 实际函数/参数与错误路径、核心测试输出；GUI/引擎另列验证，不互相替代 |
| Godot 配置、入口、Autoload 或引擎要求变化 | [项目配置](../card-demo/project.godot)、[架构](architecture.md)、[文档导航](README.md)、共享现状；必要时讨论包背景 | 配置行/源码与实际引擎 `--version` 分别记录；兼容性需运行验证 |
| 玩法流程、结算或数据版本变化（须另获授权） | 对应源码/规格、批准决策、架构版本边界、共享现状；候选和 Agent 包核陈旧摘要 | 实际合法/失败操作、写档/读档或迁移检查，不能仅用文件存在证明 |
| 新想法、候选或团队决定 | 想法池/问题总表/候选规划/决策中的对应主责位置；Agent 包按受影响背景核对 | 提出者确认的概括；批准需确认者、范围与日期，不附私人对话 |
| 新验证、阻断或未验证项变化 | 共享现状与相关验证记录；若架构结论被推翻则同步修正架构 | 实际命令/操作、环境条件、可检查输出与观察；不得把未运行写成通过 |
| GitHub 交付 | 负责人核待提交路径、忽略项和远端结果；共享现状只记录真实结果 | 实际差异、提交标识与推送/远端可访问结果；只配置 remote 或准备文件不等于上传 |

证据只保留足够核对的项目相对路径、公开可共享输出与事实，不把本机绝对路径、凭据、令牌、私人对话或用户存档放入共享文档。必要本机详情留在 `.local/`，公开摘要去除隐私；不要通过把日志挪出忽略目录来绕过限制。

## 5. 并发编辑与 GitHub 门禁

- 同一时间共享文档只由一个明确所有者落笔；独立文档可以并行。每轮明确哪些文件由谁维护；独立文档整理者不自动获得共享状态、实现或远端推送权限。
- 编辑既有文件前先读取；提交修改前再核当前内容/差异，发现他人新改动则保留并局部合并，不用旧快照整文件覆盖。无法判断冲突时将分歧和证据交给所有者。
- 跨文件更改由所有者协调；个人完成不代表其他并行模块完成。交接说明“尚待实现对齐/尚待验证”，合并后负责人核一致性再报告完成。
- GitHub 操作由有提交/推送权限者进行：核明确范围、工作树差异、忽略目录与敏感信息，确认目的仓库和实际远端结果。不为上传而顺便扩展游戏方向、自动发布游戏或泄露本机设置。
- 本机快照、配置、日志以及私人资料不纳入提交。用户明确要求的[Godot压缩包、校验清单与许可](../.setup/Godot/README.md)可随源码分发；裸exe和解压缓存仍不提交。共享状态中只写经核实的提交/推送结果；失败或权限不足如实保留，不将准备完成写成已经上传。

## 6. 最小维护检查清单

- [ ] 已读共享现状/相关规格与明确权限，没有把候选当批准。
- [ ] 新事实有源码或实际操作证据；无新事实时没有虚造更新。
- [ ] 受影响主责文档已更新或已向所有者交接，未重复复制正典。
- [ ] 快照只代表生成时点的本机观察，没有持续监控或游戏通过声明。
- [ ] 实现/静态检查/核心测试/GUI/引擎运行/完整玩法/远端上传的结果分别表述。
- [ ] 未覆盖并行改动；提交范围不含绝对路径、凭据、私人对话或 `.local/` 内容。
