# Cun 团队文档

Cun 由用户与伙伴共同开发。正式游戏方向尚未确定；当前先搭建便于合作、试错和实机验证的舞台，不先确定完整架构。

## 每次工作必读与启动入口

- **[共享项目状态](../PROJECT_STATUS.md)**：先核当前阶段、实际实现、已验证/未验证和允许范围；每轮结束核对更新。
- [Agent工作入口](../AGENTS.md)：阅读、修改、文档维护和权限约定。
- [Windows启动器](../Launch.cmd) / [使用说明](../launcher/README.md)：当前原型的本机游戏/编辑器入口，不是独立打包游戏。
- [文档维护规划](documentation-plan.md)：共享状态、候选、决策、源码与本机快照各负其责。

## 新游戏方向：整理想法与问题，先不急着制作

- **[交给自己Agent的完整讨论材料](design/agent-discussion-kit.md)**：自包含背景、40题候选/取舍/建议、讨论提示词与个人摘要格式；每人自己讨论、自己查看，不要求统一交票。
- [讨论导图与群发说明](design/discussion-map.md)：辅助查看主干，不是要求集中回收的流程。
- [奇思妙想池](design/ideas.md)：团队持续记录新点子的入口，收录不等于采纳。
- [40题问题总表](design/questions.md)：方向、设计、实施三轮处理，全部尚未定案。
- [8题简短选择表](design/ballot-round-1.md)：可选辅助，保留其他、不确定与反对意见，不要求提交。
- [离线讨论页](../share/team-discussion.html)：自包含脑图、选择票和问题总览；不收集或保存回答。

## 当前候选规划：尚未批准实施

- [石化世界与异灵远征规划](design/project-plan.md)：整理用户和伙伴讨论、世界观、操作方案、卡牌/融合、美术与现有骨架接入；明确建议与未决项。
- [首个可玩版本计划](design/first-playable.md)：最小范围、分段交付、远征/存档数据边界和真实试玩判据。

这是一版候选规划，不代表团队已选定操作、美术或正式引擎，也不意味着新玩法已实现。

## 按需填写，不要求全部建立

- [游戏简报](templates/game-brief.md)：比较候选方向。
- [实验记录](templates/experiment.md)：验证一个风险或假设。
- [决策记录](templates/decision.md)：留下选择理由与回退条件。
- [试玩记录](templates/playtest.md)：记录真实操作与观察。

复制模板后放入 `docs/` 下自行命名；只记录影响下一步行动的信息，不为填表而填表。

## 现有原型与事实边界

[card-demo 项目配置](../card-demo/project.godot)显示：项目名为“灵伴回合冒险 MVP”，`config/features` 标记为 `4.7` 与 `GL Compatibility`，入口是 `MainCity.tscn`，已有数据、游戏、UI、战斗四个 Autoload。配置标记不等于已验证本机安装或可正常运行。

该项目是保留的 Godot 原型，不迁移，不认定为正式游戏方向；未来正式工程的位置与引擎另行确认。本文档未报告任何实机验证结果。
