# 奇思妙想池：先接住，再澄清，再决定

用途：本文件是 Cun 团队所有新想法的长期入口。**记录不等于采纳，喜欢不等于开工，AI 整理不等于团队批准。** 当前没有已批准的新增玩法任务。

相关入口：[问题清单](questions.md) · [首轮选择票](ballot-round-1.md) · [讨论导图与群发说明](discussion-map.md) · [候选规划](project-plan.md)

## 怎样用，尽量不增加负担

1. 谁想到什么，先写一句原话或自己确认过的概括；不要求先写策划案。
2. 整理者补上“玩家获得什么体验、影响什么、需要问谁”，不能偷偷改掉原意。
3. 重复想法引用同一个编号，保留不同意见；相互冲突的方案并排，不强行拼起来。
4. 涉及方向的挂到 Q 编号讨论；值得验证的转成一个小实验；只有负责人和伙伴明确确认后，才变成实施任务。
5. 延后/不采用也保留原因。除误录或本人撤回外，不删除旧想法；更正用说明保留来龙去脉。

### 状态与出口

`已收录 → 待澄清 → 待讨论 → 待实验 → 已确认 / 延后 / 不采用`

“已确认”必须写确认者、日期、采用范围、关联决策/任务；投票只是参考。当前表中的“已收录”“待讨论”不意味着满足后续状态。

## 从想法到决定

重要讨论用[短决策模板](../templates/decision.md)，风险验证用[实验模板](../templates/experiment.md)。不是每条想法都要另建文件；只有真正有决定或实验时再建。

处理记录只写发生过的结果。不得写虚构票数、默认赞成、替人认领任务或“大家已同意”。原型数量、美术批量、云部署、模型/API费用、对外发布仍需相应明确授权。
