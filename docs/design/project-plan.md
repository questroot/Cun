# Cun 候选方向规划：石化世界中的异灵卡牌远征

状态：**供团队讨论的规划 v0.1，非已批准的制作规格**。由用户提供的聊天截图、当前文字要求和现有原型代码整理；不把伙伴的建议当作全员共识，不宣称已验证乐趣。暂用“石醒”作内部讨论代号，不代表正式名称或商标可用性。

当前阶段按用户要求先整理思路、问题与伙伴选择，**不据本候选方案直接开工**。持续收录见[奇思妙想池](ideas.md)，未决事项以[问题总表](questions.md)为入口，分享与首轮选择见[讨论包](discussion-map.md)。本文件中的推荐不是默认投票答案。

## 1. 一句话与玩家动机

**世界石化之后，你率先醒来，借助文明传说留下的异灵卡牌深入遗址，组队、融合、带回战利品，逐步找回让世界复苏的方法。**

玩家短期想“带回这张好卡”，中期想“完成自己的阵容和融合组合”，长期想“救回重要的人、弄清石化原因”。剧情不另开一款游戏：遗址、风险选择、卡牌与复苏进度共同推进它。

定位建议：先单机的 2.5D 斜俯视冒险 RPG，战斗侧以卡牌构筑与自动回合战斗为主；肉鸽提供当局变化，搜打撤提供收获损失的张力。不在第一版同时实现实时动作 RPG、完整游戏王规则和联网自走棋。

## 2. 聊天中已有的方向、仍未定的部分

| 状态 | 内容 | 处理方式 |
| --- | --- | --- |
| 用户本次明确给出 | “全世界都变成了石头，我复活了” | 作为候选规划的叙事核心；具体石化对象和原因仍需定义 |
| 讨论中反复出现 | 鬼怪/卡牌收集、养成、冒险、构筑、剧情 | 合为一个玩家循环，不各建独立大系统 |
| 讨论中的强倾向 | 2.5D 斜俯视；非写实；水墨动态与科技感结合 | 先做一屏视觉样张确认，不视为已经锁定像素或 HD-2D |
| 讨论中的倾向 | 先单机 | 按单机安排最小闭环；最终平台和是否联机待确认 |
| 讨论中的分歧 | 自走棋/卡牌战斗，还是自己操控主角实时战斗 | 推荐探索手动、战斗自动并保留少量主角指令；必须在扩写战斗前确认 |

| 合作方式 | 人提供想法与试玩，AI 整理、整合、实现与检查 | AI 不替代真实试玩、方向确认、素材授权和人类验收 |

本规划不把《石纪元》《宝可梦》《游戏王》《哈迪斯》《星露谷物语》《DNF》的角色、名词、UI 或独有设定搬进项目。这些名称只用于沟通石化前提、收集、组合、视角和操作感。

## 3. 世界观：先把“石化”定义清楚

以下均为建议，尚非正典。

### 3.1 石化的边界

- “全世界变成石头”建议理解为**全球人类遭遇石化灾变**，不是海水、空气、太阳和所有建筑全部变成同一块石头。其他动物、植物是否受影响暂不定，首区不靠这些答案推进。
- 玩家也是曾被石化的人，苏醒不是死亡后的无限复活。为什么率先醒来是主线问题之一；不提前认定玩家是唯一能苏醒的人。
- 石像不是可随便敲碎的矿石。是否还有意识、能否修复裂损，以及何时可以复苏，都是世界需要逐步回答的问题。
- 民俗异灵与普通人不同：它们由故事、记忆和仪式留下的“回响”在灾变后显现。此解释是游戏原创，不冒充任何现实文化的传统说法。
- 用“异灵”作总称，具体再分妖怪、亡魂、精怪等；神祇和仍在实践的宗教对象不默认列为可捕捉怪物。

### 3.2 系统与科技水墨

建议把“系统”设为残存的复苏辅助装置：它能扫描记忆回响，把可缔结契约的异灵记录为卡牌；自身资料残缺，不是无所不知的外挂。

界面可偶尔吐槽，但只用于短暂缓和气氛，不破坏重要剧情。“系统就是开发者”可以是彩蛋，不作为核心世界真相，也不要求运行时调用大模型。

水墨表现回响、封印与灵体；几何线、扫描环和清晰边框表现辅助装置。两种视觉语言有叙事分工，而不是所有物体都叠水墨滤镜。

### 3.3 首章可玩的叙事问题

建议开局：玩家在废弃记录站醒来，发现一名重要人物仍是石像。装置只能指出旧城遗址中存在一段复苏记录，无法直接救人。

第一段目标不是“立刻拯救全世界”，而是“带回第一份有效记录”。首次返航后装置解析一段记忆，证明复苏有可能，但还缺条件。

首个选择：已经拿到记录后，是否继续深入带回一张稀有异灵卡。两种选择都能推进体验，剧情任务不逼玩家每局必须击败首领。

失败后，记录作为未撤离战利品丢失，玩家可以重试获取；不重播整段开场，不删除既有剧情进度。复苏重要人物的最终承诺、石化元凶和结局先不写死。

## 4. 玩家究竟怎么操作

### 推荐方案 A：手动探索，布阵自动战斗＋少量主角指令

| 时段 | 玩家操作 | 游戏负责 |
| --- | --- | --- |
| 据点 | 查看收藏、选队、查看任务、出发 | 校验拥有关系与出发条件 |
| 遗址探索 | WASD/点击移动，交互，选择路线与搜寻点 | 场景反馈、交互范围、遭遇与状态管理 |
| 战前 | 更换上阵异灵、调整九宫格、选择战术 | 明示敌情和合法阵容 |
| 战中 | 可选少量回合开始时的主角指令；无需逐只指挥普攻 | 自动选择合法行动与目标、结算、播放反馈 |
| 战后 | 检查伤势与收获，恢复、融合、撤离或深入 | 当局状态延续、展示成本与风险 |

先沿用现有回合顺序，不把自动战斗误写成必须实时跑动的标准自走棋。主角可以是契约者/指挥者，保留现有固定主角＋四异灵上阵结构用于验证；这不是最终人数决定。

首个自动战斗检查点可以暂时不做主角指令。加入指令时先只试 3 个清晰效果、每轮最多 1 次，明确资源消耗和目标选择；不引入完整抽牌、连锁、反击时点与陷阱规则。战斗必须在未使用指令时仍能推进。

### 如果团队选择方案 B：实时操控主角战斗

这会变成“动作冒险＋自动异灵队伍”，需要攻击/闪避、攻击范围、敌人行为、碰撞、动作资源和镜头设计。现有主城移动可以复用，但当前战斗不等于已经具备动作战斗基础。

B 不是给 A 加个按钮；它是另一条制作路线。选择 B 时先削减复杂融合、卡组规则和当局经济，单独验证一场动作遭遇。不要把“像 DNF 一样操作”与“完全自走棋”同时列为首版必需。

## 5. 一局与长期成长怎样扣在一起

### 5.1 推荐循环

据点选队 → 进入小遗址 → 选择路线/搜寻 → 自动战斗 → 获得卡牌或复苏线索 → 调整/融合 → 撤离或继续 → 成功入库 / 失败损失当局收获 → 下一次远征。

肉鸽不是每次换贴图：当局获得的异灵、恢复机会、遭遇组合，至少有一项能改变阵容或路线决策。搜打撤不是多一个返回按钮：当局生命和恢复资源连续消耗，继续深入会冒着失去已经获得的东西的风险。

### 5.2 第一版风险合同（建议）

| 对象 | 成功撤离 | 失败 |
| --- | --- | --- |
| 出发前已有收藏、队伍模板 | 保留 | 保留，不永久杀死珍藏卡 |
| 当局找到的卡牌/材料/剧情任务物 | 经一次结算转入仓库或任务进度 | 丢失，任务可重新获取 |
| 当局临时强化、伤势、恢复次数 | 结束并清理 | 结束并清理 |
| 当局战斗经验 | 撤离时才转为永久经验，或首版暂不做成长 | 不立即计入永久成长 |
| 已永久完成的剧情节点 | 保留 | 不回滚 |

首版保留借出的基础队伍或安全出发阵容，避免失败后无队可玩。暂不做付费抽卡、玩家交易、卡牌死亡和保险系统。

撤离建议在明确的安全节点/出口进行，不提供任何战斗中无代价瞬间逃跑。深入前显示下一步风险信息；未知敌情可以存在，但不可隐瞒已经确定的规则和消耗。

全队失去战斗能力、或明确的遭遇失败条件，结束远征；沿用当前回合上限时必须在 UI 告知，不能无提示突然失败。关闭游戏与读档策略在存档实现阶段明确，首版目标为安全节点可续玩，不承诺战斗任意帧续档。

### 5.3 长期成长

优先扩展收藏选择、融合配方、区域情报和据点功能，避免只靠永久数值碾压让风险消失。剧情推进与收藏相关，但不要求为了看主线刷齐全图鉴。

货币首版最多一种，用于少量恢复/准备选择；不能同时承担买卡、融合、装备、皮肤和抽奖全部职能。商城皮肤先理解为远期装扮想法，是否真钱售卖另行确认。

“七宗罪装备”若保留，可作为远期七条高风险构筑主题，而非额外强加七套升级系统；原型阶段不做。

## 6. 卡牌与融合：避免变成自动升星

- 卡牌代表异灵实体/契约，模板 ID 与玩家拥有的卡牌实例 ID 分开。
- 文化来源字段用于考据；水域、夜行、变形、守护、契约等玩法标签用于跨文化组合。来源不同不代表天然敌对或善恶。
- 每只异灵先有一个容易描述的战斗职责，主动/被动数量不照搬旧原型的四被动硬指标。
- 融合由玩家主动确认；材料、产物、消耗、失去的能力和得到的能力都明确展示，不因相邻站位自动消耗卡牌。
- 首版只允许消耗当局搜到的材料卡；不消耗出发前永久收藏，不允许把据点借出的基础单位合成后反复带回刷收益。
- 融合产物是未撤离战利品；材料在当局移除，撤离时只能带回产物，不能产物和材料双重入库。
- 无合法配方时不消耗材料；重复点击只能发生一次。融合过程在战后安全节点操作，不在战斗动画中修改阵容。
- 跨文化融合产物标记“原创异灵”，图鉴分开写现实出处与游戏演绎。

示例只用于机制验证：一张擅长控制的异灵和一张持续输出异灵，融合成延长控制但牺牲治疗能力的单位。它不是无脑数值全面升级，应产生是否值得消耗材料的判断。

## 7. 美术与剧情如何落到一屏、一局

### 7.1 美术候选：低成本 2.5D 科技水墨

- 首选斜俯视、固定镜头方向、2D 场景和角色，先不强求真实 3D 与 HD-2D 灯光。
- 静态场景：低饱和石青/灰白遗址、清楚道路和石像轮廓，局部留白。可交互目标和危险必须易辨认。
- 角色：简化卡通比例和统一轮廓，卡面允许更精细插画；头像、立绘、场内单位必须能认出同一角色。
- 动态：墨线扩散、封印印记、粒子散墨用于技能与事件；扫描环和细线用于系统提示。
- UI：布局、文字和数值保持清晰，水墨只作边缘/转场等装饰；不让墨渍盖住目标、血条或卡牌效果。
- 稀有度/阵营不只靠颜色区分，同时用符号与文字。
- 像素、高清卡通、水墨不是自动兼容的素材拼盘。若决定像素风，另定逻辑像素尺寸、缩放、轮廓和动画规则，再生产。

先比较两张同构图样张：简化卡通＋科技水墨，像素＋少量水墨特效。用一屏主角、两只异灵、一个交互物和短 UI 验证辨识度与制作成本。**样张获确认后才批量生成素材**；此文档没有提供任何已验收视觉。

音频先覆盖命中、受伤、获得、融合、撤离与失败的必要反馈，不先制作完整音乐库。有人实际观看/听验后再判断是否舒服、顺畅。

### 7.2 首段剧情与地图内容一起写

- 开场：只交代苏醒、石像和眼前目标，之后立即给移动与交互。
- 遗址线索：一段短记忆既补充人物动机，也解释这次探索物品的价值。
- 风险节点：已得到线索时出现继续深入的诱惑，不用长对白替玩家做决定。
- 返回：据点产生一个可见变化，展示确实带回了东西；不只弹“任务完成”。

文本可跳过/回看，关键操作与代价仍清楚。重要剧情不靠 AI 每次随机编写；先写少量人工确认的剧情节点与固定触发条件。

## 9. AI 与伙伴的协作

团队按任务而不是按固定职位分工：方向/范围由创意负责人确认；文案、美术、玩法想法可分别认领；每项产物明确文件、输入、输出和一位检查者。AI 负责整理、受限实现、资源登记、检查与整合，遇到会改变操作路线、重要剧情、许可或费用的问题先列选项。

“AI负责跑通”意味着在实际引擎中验证可操作结果，不是只生成文件和测试日志。AI 无法操作、未实际运行、没有观察画面/音频时，必须标注未验证。伙伴仍负责真实试玩与体验判断，发现卡点要给操作步骤和现象。

截图提出的云端 harness/集中整合可以列为后续协作工具需求，当前不部署服务、不外发截图、不购置云机器。GitHub 小 PR 与现有资源登记先够用。

AI 在制作期辅助生成固定内容；首版离线可玩，不依赖运行时 LLM、随机数值生成或玩家付费 API。

## 10. 待拍板：只先决定会改变制作路线的事

1. **操作路线**：A 探索手动＋自动回合/主角指令，还是 B 实时动作主角＋自动队友？推荐 A，用户与伙伴尚未确认。
2. **画面路线**：简化卡通科技水墨，还是明确的像素/HD-2D 路线？先选样张方向，不把聊天里的多种提议全叠上。

首区文化、首发平台（建议先 Windows）、石化是否影响其他生命、长期装备与剧情结局，可以在第一版边界内继续讨论。没有以上两项结论时，可以做现有原型验证与草图，不能把某一路线写成团队已批准。
