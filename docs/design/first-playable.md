# 首个可玩版本：一次能带回东西的石化遗址远征

状态：**候选实施计划，尚未开始实现或实机验收**。依赖[方向规划](project-plan.md)中的操作/画面选择；下文按方案 A“手动探索、自动回合战斗”安排。若选择实时动作方案 B，战斗阶段必须重排，不同时实施两条路线。

当前先完成[方向选择与问题整理](discussion-map.md)，本计划保留为候选，不等于已排期实施。未决项集中在[问题总表](questions.md)，新想法写入[想法池](ideas.md)。

## 1. 第一版要证明什么

不是做完所有系统，而是证明：玩家能够理解搜寻→调整→战斗→带回的流程；卡牌获得/融合会改变决策；继续深入与撤离之间有真实权衡。

建议一次完整远征以 10–15 分钟为目标，**这不是实测结果或制作工期**。实际过长就减少遭遇/演出，过短就调整选择密度，不先增加内容量。

## 2. 建议边界

| 内容 | 第一版边界 |
| --- | --- |
| 平台/联网 | 先 Windows、本地单机；正式首发平台待确认 |
| 场景 | 一个据点、一个短遗址；固定可读地图＋少量节点内容随机，不做无限程序地形 |
| 路线 | 约 5–7 个选择/交互节点，安全撤离口在前段与后段明确出现 |
| 队伍 | 暂保留一个主角＋四异灵和九宫格，先验证已有结构 |
| 卡牌 | 8 个基础异灵候选模板＋2 个融合产物；美术先用明确授权的占位或简化轮廓 |
| 构筑 | 2 个容易理解的组合方向，2 条主动确认的融合配方 |
| 遭遇 | 至少 3 种确实不同的敌方构成/行为；首领不是首个闭环必需 |
| 消耗 | 跨战斗生命保留；当局最多少量恢复机会，初始数值经试玩调节 |
| 剧情 | 苏醒、遗址线索、首次返回 3 个短节点；一个可重复获取的任务物 |
| 战利品 | 当局卡牌与一种任务/材料资源；不先增加多币种经济 |
| 输入 | 探索移动/交互、战前布阵、战后融合/恢复/撤离；主角指令单独验证后加入 |
| 不做 | 联网、账号、交易、付费商城、七套装备、全世界地图、全图鉴、实时 LLM、完整陷阱连锁 |

数量是控制范围的建议，不是最低内容 KPI。若资源生产拖慢验证，可减少卡牌，仍须保留两种可比较的构筑和至少一次有意义的风险选择。

## 3. 分段交付，不一口气重做原项目

### P0：确认基线与隔离

- 先确定可用 Godot 版本，记录实际版本；当前配置声明 4.7 不证明机器上已安装。
- 保留原型，真实走一遍主城→选关→编队→战斗→返回；记录阻断点和未验证项。
- 选择新候选原型目录和独立存档位置，不覆盖原项目；复制必要代码/资源前核来源和引用。
- 使用同一份已确认的输入/视角约定；不在此阶段顺便重构所有管理器。

**交付**：一个能按明确步骤启动的基线，原项目与用户存档无破坏。引擎缺失时只继续独立的设计/占位资源工作，不称基线已验收。

### P1：一场可理解的自动战斗

- 复用回合、目标池、演出回执、状态与九宫格。
- 为我方增加自动策略：合法奥义可用时按职责选择，否则普攻；治疗/净化要有有效目标，不浪费在无作用对象上。
- 明示单位的职责、当前行动、目标和关键状态；非程序伙伴可以解释输赢原因。
- 此阶段先不实现完整指令卡；如要加入每轮一个主角指令，应有独立输入等待/跳过入口和资源校验，不再要求逐只宠物点击。

**交付**：不靠开发者后台操作，一场战斗能结束、失败可重试；改站位/队员确实改变一个可观察结果；自动流程不永久等待 turn_requested 的玩家输入。

**调整条件**：如果自动战斗不可理解，先改善行为与信息；如果可理解但参与感不足，再试有限指令。不要立即补实时攻击和闪避。

### P2：最小搜打撤闭环

- 在小遗址设置搜寻点、战斗点、安全撤离点和深入选择。
- 生命/恢复次数跨遭遇接续，不创建新战斗就满血。
- 获得卡牌后放入当局战利品，可用于本次布阵；不立即写入永久收藏。
- 胜利只更新当局状态，撤离才提交永久收益；失败结算不提交。
- 在退出安全节点、读档、重复点击与重复进入结算时维持一致性。

**交付**：搜到卡后撤离，仓库得到一次；搜到卡后失败，仓库不增加；重新进入游戏不能重复领取。玩家能说出继续深入在冒什么风险。

**调整条件**：一直无脑深入则增强连续消耗/改善风险信息；一直第一出口撤离则调整深层收益/早期难度。不要先以永久珍藏死亡制造压力。

### P3：一次改变决策的融合与剧情回流

- 仅在安全节点提供融合，显示配方、材料和结果；本次获取的材料才允许被消耗。
- 加入两条差异化组合，避免所有鬼怪都只是护盾/回血/增伤数值不同。
- 加入短开场、任务线索和回城变化。剧情物可以重试获取，已有剧情完成标记不因失败删除。
- 新卡、融合结果和任务线索分别有获得反馈和入库状态。

**交付**：玩家能指出一次“因为搜到/融合了某卡而改变站位、队伍或路线”的决策；融合不能双领材料与产物；任务路径失败后可恢复。

### P4：只打磨一段代表性体验

- 按批准的一屏风格做据点一角、遗址一段、主角与少量异灵；不用先做全部角色。
- 覆盖关键动作/交互提示、卡牌与融合界面、必要音效和一个水墨特效。
- 检查角色轮廓、可走区域、目标提示、墨效遮挡、文本适配；记录实际设备和帧时间/卡顿。
- 先前文字中的 10–15 分钟目标、节点数量、资源次数在这里通过实际游玩修正。

**交付**：伙伴无需开发者代操作，能完整玩一局并理解收获与损失；没有阻断；实际观感与声音接受人工检查。性能目标在测试前按目标设备确定，不临时为通过改口径。

## 4. 最小数据合同

以下是接口设计建议，不是当前已实现的类型。

| 数据 | 应含的信息 | 不应混入 |
| --- | --- | --- |
| CardDefinition | 稳定模板 ID、职责、标签、技能引用、美术引用、来源/演绎说明 | 某玩家血量或拥有数量 |
| OwnedCard | 实例 ID、模板 ID、已批准的永久成长字段 | 当局未撤离奖励 |
| RunState | run_id、阶段、随机种子/已确定节点、队伍实例、生命/状态、消耗、战利品、当前安全节点 | 对永久仓库的即时奖励写入 |
| FusionRecipe | 配方 ID、所需材料与数量、产物、限制 | 任意字符串执行代码、不透明随机生成技能 |
| BattleState | 参战运行态、行动队列、冷却、效果、动作序号 | 永久成长和存档事务 |
| SaveEnvelope | save_version、永久收藏、剧情标记、可续远征、已结算 run_id | 引擎节点对象、私人密钥 |

- 先检查配置 ID/引用/资源路径，再打开场景。未知条目要给出可定位错误，不默默变成默认怪物。
- 当局伤势与队伍修改由 RunState 接收；战斗场景退场不直接永久奖励。
- 同一 run_id 的收益只提交一次；本地将仓库、剧情进度、远征结算标记作为同一保存快照，避免两个独立文件一个成功一个失败。
- 本地写入使用临时文件/可靠替换及旧档恢复方案，写入失败可报告和重试；未成功写入不宣称入库完成。
- 新档版本与旧宠物原型隔离。旧档迁移是另一个显式任务，不悄悄读取后改写。
- 保存已生成路线/必要随机状态，避免每次读取同一安全存档就刷新战利品。首版不承诺防修改的竞技反作弊。
- 原型卡牌/配方 ID 稳定，改名不改 ID。文化出处与原创演绎分开，未核验素材不能因 AI 生成就标成可商用。

## 5. 伙伴怎样参与，不用先填一整本策划案

| 可认领的工作 | 必要输入 | 小交付 | 验收者 |
| --- | --- | --- | --- |
| 世界与剧情 | 石化前提、首段目标、角色动机 | 三段短节点＋触发条件 | 创意负责人＋试玩者 |
| 玩法/内容 | 一次想产生的决策、卡牌职责 | 一组卡/一条配方/一个遭遇 | 另一位伙伴实际试用 |
| 视觉 | 同一画面构图、目标分辨率与风格候选 | 一屏样张或一个角色动作样本 | 团队先确认，再批量制作 |
| AI/程序整合 | 当前明确的小目标、文件范围、验收操作 | 可启动的小变更＋实际结果/未测项 | 伙伴检视和实机复验 |
| 试玩 | 可启动版本和本次要验证的问题 | 操作卡点、输赢理解、是否愿意继续 | 团队决定继续/调整/停止 |

共享场景、存档结构、卡牌 ID 和二进制源文件必须有当前修改者；AI 不接收多人相互冲突的指令后直接合并。分歧由负责人决定，未决项保留为未决。

## 6. 首次试玩只问五件事

1. 能否不经讲解，完成一次出发、获得、战斗和撤离？
2. 能否说出某单位为什么攻击/治疗了那个目标，失败因为什么？
3. 新卡/融合是否改变一次具体操作，而不是只增加收藏数量？
4. 有没有一次真正犹豫要撤还是继续？为什么？
5. 石化世界是否让你想追下一段线索，而不是只看完设定文字？

真实观察写入[试玩模板](../templates/playtest.md)。测试通过不能替代这五项体验；没有达到时缩小或调整，不以更多系统和卡牌遮盖问题。
