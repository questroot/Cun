# Cun 特效展示动图规格

> **结论先行**：5 张新参考设定图可以转展示动图，但**当前被出图通道额度阻塞**（本月 50 点配额已用尽），生成跑不动。本文件先把节奏、帧率、输出与预算定死，额度一到即可逐条执行，不需要再返工设计。
>
> 定位：**展示动图 ≠ 运行资产**。它用于造型评审、设定集与对外演示，进不了引擎；游戏内循环特效仍由 `build.py` 的 96×96 八帧图集保证。

## 一、输出规格

| 项 | 值 | 说明 |
|---|---|---|
| 源图 | `showcase/` 下 5 张 PNG | 底图即各自造型设定图 |
| 输出格式 | 透明底 GIF（主）+ MP4（备） | GIF 用于嵌入文档与演示 |
| 尺寸 | 透明底 GIF 固定 240×240 | 通道限制，尺寸不可自定义；标准 GIF 长边 ≤480px |
| 帧率 | 30 fps | 取自档位表（8/12/15/24/30/60），不取 13、17 这类值 |
| 时长 | 5 秒（150 帧） | 通道最短 4 秒，取 5 秒留出完整三段 |
| 音轨 | 关闭 | 展示动图不需要音轨 |
| 命名 | `fx_<特效键>_show_v1.gif` | 如 `fx_H06-hammer_show_v1.gif` |
| 循环方式 | 非循环，`hold_last` 末帧停留 | 攻击类一次性动作，不做根位移 |

**已知通道边界（不要对结果抱超出此范围的期待）**：透明底 GIF 尺寸被钉死 240×240；镜头由生成模型产出，是生成不是剪辑，无法精确指定关键帧在第几帧——所以下面的节奏表是**验收判据**，不是生成控制参数。成片若与节奏表有偏差，按判据判定是否可接受。

## 二、节奏三段分配（通用）

按预备 / 出手 / 收招 = 30% / 15% / 55%，5 秒 30fps 共 150 帧：

| 段 | 时间 | 帧区间 | 作用 |
|---|---|---|---|
| 预备 anticipation | 0.00–1.50s | 1–45 | 让玩家看清造型从何而来，避免"凭空出现" |
| 出手 strike | 1.50–2.25s | 46–67 | 速度最快，爆发点在此段 |
| 收招 recovery | 2.25–5.00s | 68–150 | 提供反馈与余韵，长度足够才有重量 |

- `hit_frame = 52`（约 1.73s）：爆发点，冲击波/闪光/炸开都落在这一帧
- `fx_frame = 52`：与 `hit_frame` 同帧，不放 ±1 帧之外
- 末帧 `hold_last`，不回卷

**关键帧剪影判据**：把 1 / 45 / 52 / 150 四帧涂黑排成一行，必须能一眼区分"还没发生 / 正在落下 / 已经炸开 / 散完了"。区分不出来的帧是白帧。

## 三、5 张逐张节奏表

### H06-hammer 铜锤撼地（风格锚点）
- **预备 1–45**：巨锤自上方抬起并加速下压，锤体轮廓由小变大，地面先出现裂纹预兆
- **出手 46–67**：锤头砸地，扇形冲击波向外炸开，碎石与尘土飞溅（爆发点 52）
- **收招 68–150**：冲击波持续外扩、碎石回落、尘土消散至画面清空

### H01-banner 血旗横扫
- **预备 1–45**：旗杆自左侧竖起，旗面收拢，血色弧线尚未展开
- **出手 46–67**：旗面猛然展开横扫，血色冲击弧随旗势拖出（爆发点 52）
- **收招 68–150**：旗面飘扬减速，冲击弧外扩散散
- **返工要求（上轮评审未达标项）**：旗面右端必须闭合，不得留撕裂缺口；血色冲击弧边缘必须硬，不得羽化。这一张在转 GIF 前需先重出静态图。

### H02-seed 飞种围猎
- **预备 1–45**：三枚种荚自三个方向出现，缓慢向中心移动，尖刺收拢
- **出手 46–67**：三荚同时收拢到位，尖刺张开，中心亮起聚拢闪光（爆发点 52）
- **收招 68–150**：包围圈收紧后稳定，尖刺微颤，中心闪光衰减

### H02-grove 森冠禁环
- **预备 1–45**：藤蔓自地面钻出，沿环形两侧生长
- **出手 46–67**：藤环合拢闭合，荆棘刺向内倒伏，中心森冠树影浮现（爆发点 52）
- **收招 68–150**：环体稳定，树影明暗呼吸，荆棘轻微摆动
- **循环可行性**：这是环形技，末帧藤蔓状态与首帧一致，若需循环版本可改 `loop_start=1 / loop_end=150`

### H02-stomp 荆棘践踏
- **预备 1–45**：地面隆起，裂纹张开，土层微颤
- **出手 46–67**：巨型荆棘地刺冲天而起，土层碎块炸飞（爆发点 52）
- **收招 68–150**：碎块回落，地刺保持直立，尘土落定

## 四、亮度与遮挡约束

| 项 | 上限 | 本批实测/设计值 |
|---|---|---|
| 全屏闪光频率 | < 3 次/秒 | 每张仅 1 次爆发闪光，5 秒内 1 次 = 0.2 次/秒 ✅ |
| 叠加方式 | 同一种，不混用 | 发光类统一**加法（additive）**；烟尘类统一透明混合。本批全为发光，统一加法 |
| 同屏高亮特效 | ≤ 2 个 | 展示动图为单体特写，不适用；回落到运行时需复核 |
| 特效区域 | ≤ 30% 屏幕 | 展示动图不适用；运行时需复核 |

## 五、回落到运行图集的预算（给数字）

这批造型若后续按参考重绘进运行图集，预算如下（口径写在数值后）：

| 项 | 数值 | 推导 |
|---|---|---|
| 单组贴图数 | 1 张 | 768×96 横排八帧；≤4 张上限 ✅ |
| 单组未压缩内存 | 288 KiB | 768 × 96 × 4 字节（RGBA8888） |
| 56 组总计 | 15.75 MiB | 288 KiB × 56 |
| 生命周期 | 0.70 秒 | 攻击类；≤2 秒上限 ✅ |
| 天气/状态 | 循环播放 | 每帧 120ms，八帧 0.96 秒一周 |
| 同屏粒子峰值 | 天气 36 个 | ≤200 上限 ✅；低端机可砍半到 18 |
| 同屏特效实例 | 天气 36 + 首领施放 ≤6 | ≤8 上限在"实例"口径下需复核（36 个粒子属同一天气实例） |

**注意**：15.75 MiB 超过「粒子贴图总内存 ≤8 MB」的移动端起步建议约 2 倍。Cun 是 Windows 桌面端项目，该建议非硬约束，但若要上移动端必须砍：可改用 512×64 或改索引色，届时重算。此项**需实测验证**，不在本文件下结论。
